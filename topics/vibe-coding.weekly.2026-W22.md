## 🗞️ 头版报道

### 一. Claude Code 不再只是 IDE，而是开发者操作系统

**论点**：把 Claude Code 当 Cursor 的替代品来理解已经过时——它现在的正确比喻是 OS。

UP 主"马克的技术工作坊"过去 4 个月最被传播的视频（112 万播放）第一次把 Claude Code 三大底层能力系统讲清楚：**MCP** 是工具协议层、**SubAgent** 是任务分派层、**Skill** 是可复用工作流层。马克的关键判断是——"三者不是并列，是层级"：用户写 Skill，Skill 调 SubAgent，SubAgent 调 MCP。

**这个心智的实践含义**：多数人在 Skill 层堆代码（一个 Skill 几百行），但其实应该把复杂逻辑下沉到 SubAgent 层做编排，Skill 层只留入口。这和"App / Service / Kernel"的 OS 三层模型是同构的。

**对你做 Curio 的启发**：你现在的 `curator.py` 把 `explore` / `search` / `score` / `digest` 都在主进程跑——这就是"全在 Skill 层"的反例。M1 应该把每一个搬到 SubAgent，主入口只做编排。

### 二. ultrawork 把 vibe coding 重新定义为 vibe orchestrating

**论点**：当你能"召唤无数个 Agent 协同"，写代码的姿势从"对话"变成"指挥"。

AI 超元域 4 天前实测了 Claude Code 新发的 Workflow 功能 + ultrawork 命令——一句话能召唤多个 SubAgent 并行处理任务。Demo 里他让一个 Agent 改前端、一个改后端、一个写测试，**三件事并发跑**，最后用主 Agent 合并。14 分钟视频里能看到 Workflow 视图——任务编排像 Airflow / Prefect 那样的 DAG。

**这意味着什么**：vibe coding 的下一阶段不是"写代码"，是"编排 Agent"。一个开发者一周能产出的代码量被 5x，但**瓶颈从写代码变成了规划任务边界**——哪些事并发、哪些事串行、哪个 Agent 干啥。

**短板是什么**：Demo 里所有 Agent 共享上下文，看不到上下文隔离的机制。如果一个 Agent 写脏了上下文，整批 Agent 都会受影响。这是 Anthropic 下一版必须解决的问题。

> 📺 [AI 超元域 · Workflow 实战 · 14 分钟](https://www.bilibili.com/video/BV1KoGE6cE53) （4 天前发，最新热度）

### 三. 用 Claude Code 自动化漏洞赏金，4 万美元已落袋

**论点**：vibe coding 在严肃工程领域第一次产出真实业务收入。

UP 主"王尼互"复盘了一个真实 case：基于 Claude Code 搭一个漏洞赏金自动化 Agent，监测 HackerOne 上的 scope 变化、自动跑漏洞扫描、生成报告，三个月赚到 4 万美元。35 分钟视频里包含**整个 Agent 架构图、prompt 模板、ROI 复盘**——是少见的"真在赚钱的 Agent"案例。

**关键细节**：
- 单次扫描的 Claude Code API 成本 ≈ $0.40，但产出一份合格的 HackerOne 报告平均能赚 $200—500
- 瓶颈不在 LLM 能力，在**对漏洞模式的工程化抽象**——王尼互用了 14 个自定义 Skill 处理 SQL 注入、IDOR、SSRF 等模式
- "**Agent 不会发现新漏洞，Agent 是把已知漏洞模式扫得更密**" —— 这句话值得 vibe coder 反复念

**对你的启发**：不是每个领域都需要新 Agent。把"已知工作流自动化"是 99% 现实场景。

### 四. 工具切换的疲劳期：Cursor → Claude Code 的真实体感

## 💬 访谈版「他们这周说了什么」

### ◆ 姚顺宇 · 前 Anthropic 研究员 / Gemini 训练师

**主持**：张小珺商业访谈录 · **时长**：4 小时 · **18 天前发，51 万播放**

姚顺宇这次访谈最有价值的不是他讲了什么新结论，而是他给了一个**圈外人极少能听到的视角**——训练侧 know-how 的隐秘度，远比公开论文说得严重。

他反复强调：**Anthropic 的 RLHF 流水线"和论文里写的是两件事"**。他举的例子是 Claude 3.5 Sonnet 和 Opus 用的是同一个底模，差异完全靠后训练堆出来——这种事情论文里不会写，因为说出来没法保护。这种"基础设施级 know-how"是头部实验室真正的护城河。

谈到中美差距，他的判断很干脆：**差距不在算力，在工程化经验积累**。"算力可以买，但工程师踩过的坑不能。"姚顺宇说他在 Gemini 时见过太多 PhD 重新踩 Anthropic 半年前已经踩过的坑——不是论文不够公开，而是"哪些坑能踩、哪些坑不能踩"这种判断只能靠工程师之间的口耳相传。

更微妙的是他对小团队 vs 大团队的看法：**小团队反而更适合做 frontier 模型**。"决策链短、信号纯"——大团队为了不出错会平均化所有判断，结果训练效果反而平庸。这和 OpenAI 早期 GPT-3 / GPT-4 由不到 30 人核心团队主导的事实吻合。

最让我记住的一句是他谈训练成本：**"训练大模型的核心成本不是 GPU 是时间窗口。"** 一次失败的训练损失不是钱，是错过产品发布节奏——这把训练这件事的本质从"工程"重新定义成"赌博式产品节奏管理"。

最后他提到 Gemini 1.5 → 2.0 的提升：**不来自架构，来自数据洗法**。这一句话把整个行业目前在比的"新架构军备竞赛"判了死刑——真正的增益在 data pipeline。

### ◆ 翁家翌 · OpenAI 后训练团队前研究员

**主持**：WhynotTV Podcast · **时长**：2 小时 · **132 天前发，110 万播放**

翁家翌这条访谈和姚顺宇有意思的地方是——**两个人在不同实验室、不同时间，最后讲到同一个底层判断：训练侧的瓶颈不是算法，是别的东西**。

姚顺宇说瓶颈是"工程化经验"，翁家翌说瓶颈是"标注质量"——这两件事其实是同一硬币的两面。翁家翌在 OpenAI 后训练时反复观察到一个现象：**同样的算法，标注团队不同效果差 3 倍**。所以他给出了那句让我印象很深的判断：**"RLHF 的瓶颈不在算法，在标注质量。"**

他延伸出一个对开源社区的"诊断"很犀利：**开源模型追不上闭源不是因为参数小，是因为 RLHF 数据小**。开源差距不在前 95% 的预训练（这部分论文很公开、算力也凑得起），而在最后 5% 的偏好对齐——而这部分需要的不是算法 paper，是**几十万条高质量人工标注数据**，这种数据闭源实验室都视为命根子。

他自己定义的概念叫 **"taste"**——后训练比预训练更需要 taste。"预训练靠规模和算力，后训练靠对'什么是好回答'的判断力。"这件事不能写进 paper 里，只能由懂业务的研究员自己去 calibrate 团队的标注 rubric。

整段访谈最让我有共鸣的是他对教育和生态的观察：**"清华到 CMU 到 OpenAI，三个生态对'什么是好研究'的定义完全不同。"** 国内学界更看 paper count 和顶会，CMU 看创新和方法论，OpenAI 看"能不能让 GPT 表现更好"——三种价值观会塑造完全不同的研究员。这对你（工程信息工程大四 + 搜狗实习）想往后走是个长期判断题。

> 📺 [WhynotTV · 2 小时访谈](https://www.bilibili.com/video/BV1cqcCe1ECG)

### 主编小结：两条访谈合起来读

姚顺宇 + 翁家翌的组合给了你一个**完整的"训练侧真实图景"**——
- 姚说**工程化经验是 moat**（横向：实验室之间的差距）
- 翁说**标注质量是 moat**（纵向：开源 vs 闭源的差距）

两个 moat 都不在 GPU、不在算法、不在 paper。**这是中文 AI 圈本周最值得记住的一组判断**。如果你之前以为中美差距靠"补卡"能解决，这两条访谈会校准你的视角。
